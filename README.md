# تقرير مشروع نظام إدارة المهام والمشاريع
## Project Management System

---

### 1. هدف المشروع ونظرة عامة
يهدف هذا المشروع إلى تصميم وتنفيذ نظام متكامل لإدارة المهام والمشاريع (Project Management System) باستخدام لغة **Java 25**، بحيث يجمع النظام بين مبادئ هندسة البرمجيات وبنية قواعد البيانات وتراكيب البيانات والخوارزميات ضمن تطبيق عملي واحد. يسمح النظام لمدير المشروع بإنشاء المشاريع، وتقسيمها إلى مهام رئيسية، وتفريع كل مهمة إلى مهام فرعية ومهام فرعية للمهام الفرعية، بما يحقق تمثيلًا هرميًا (Hierarchical) واقعيًا لطبيعة العمل في المشاريع الحقيقية.

لا يقتصر النظام على التخزين والعرض فقط، بل يوفر أيضًا طبقة مصادقة وتسجيل مستخدمين لإسناد المهام إلى أعضاء الفريق، ولوحة كانبان (Kanban) لتتبع حالة كل مهمة وسجل نشاط (Activity Log) يوثق كل تغيير، إضافة إلى وحدتين تعتمدان مباشرة على تراكيب البيانات والخوارزميات: الأولى تنفذ يدويًا خوارزميتي Merge Sort وQuick Sort لترتيب المهام حسب الأولوية أو تاريخ التسليم، والثانية تطبق تقنية فرّق تسد (Divide and Conquer) بأسلوب عودي (Recursive) لحساب إجمالي الجهد الكلي للمشروع اعتمادًا على شجرة المهام الفرعية المتداخلة.

وُزّعت مسؤوليات بناء النظام على خمسة أعضاء، بحيث يغطي كل عضو جزءًا مترابطًا مع باقي الأجزاء عبر نماذج بيانات وخدمات (Services) مشتركة، مما يحقق فصلًا واضحًا بين طبقة البيانات وطبقة المنطق وطبقة الواجهة، ويجعل النظام قابلًا للتوسعة والصيانة.

### 2. نظرة عامة على أعضاء الفريق ومسؤولياتهم

| العضو | المسؤولية |
| :--- | :--- |
| **العضو الأول** | المشروع والمهام والتسلسل الهرمي وقاعدة البيانات (Project + Tasks + Hierarchical Task Decomposition + Database) |

### 3. مخطط وهيكلية قاعدة البيانات (SQLite Schema)
يعتمد النظام على قاعدة بيانات **SQLite** ملفية باسم `project_management.db`. تم تصميم الجداول بعناية لدعم العلاقات الهرمية (Self-Referencing) وعلاقات الربط المتعددة.

#### 3.1 جدول المشاريع (`projects`)
يخزن البيانات الأساسية لكل مشروع.
* **المفتاح الأساسي:** `id`

| اسم الحقل (Column) | نوع البيانات (Data Type) | القيود (Constraints) | الوصف |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | المعرف الفريد للمشروع |
| `name` | TEXT | NOT NULL | اسم المشروع |
| `description` | TEXT | - | وصف المشروع |
| `start_date` | TEXT | - | تاريخ بدء المشروع |
| `end_date` | TEXT | - | تاريخ انتهاء المشروع |

#### 3.2 جدول المستخدمين (`users`)
يخزن بيانات أعضاء الفريق وكلمات المرور المشفرة.
* **المفتاح الأساسي:** `id`

| اسم الحقل (Column) | نوع البيانات (Data Type) | القيود (Constraints) | الوصف |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | المعرف الفريد للمستخدم |
| `username` | TEXT | UNIQUE NOT NULL | اسم المستخدم (فريد) |
| `password_hash` | TEXT | NOT NULL | كلمة المرور مشفرة بـ PBKDF2 |
| `email` | TEXT | - | البريد الإلكتروني للمستخدم |

#### 3.3 جدول المهام (`tasks`)
الجدول المحوري في النظام، ويدعم **التسلسل الهرمي للمهام** عبر حقل `parent_task_id` الذي يشير إلى نفس الجدول.
* **المفتاح الأساسي:** `id`
* **المفاتيح الأجنبية:** 
  * `project_id` يربط المهمة بالمشروع التابع له.
  * `parent_task_id` يربط المهمة الفرعية بمهمتها الأم (تسمح بـ Task &rarr; SubTask &rarr; SubSubTask).
  * `assigned_user_id` يربط المهمة بالعضو المسؤول عنها.

| اسم الحقل (Column) | نوع البيانات (Data Type) | القيود (Constraints) | الوصف |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | المعرف الفريد للمهة |
| `project_id` | INTEGER | FOREIGN KEY &rarr; `projects(id)` ON DELETE CASCADE | معرف المشروع التابع له |
| `parent_task_id` | INTEGER | FOREIGN KEY &rarr; `tasks(id)` ON DELETE CASCADE | معرف المهمة الأم (Null للمهمة الرئيسية) |
| `assigned_user_id` | INTEGER | FOREIGN KEY &rarr; `users(id)` ON DELETE SET NULL | معرف المستخدم المسؤول |
| `title` | TEXT | NOT NULL | عنوان المهمة |
| `description` | TEXT | - | وصف تفصيلي للمهمة |
| `priority` | INTEGER | NOT NULL (e.g., 1-High, 2-Med, 3-Low) | مستوى الأولوية (للترتيب بـ QuickSort) |
| `due_date` | TEXT | - | تاريخ التسليم (للترتيب بـ MergeSort) |
| `status` | TEXT | DEFAULT 'To Do' ('To Do', 'In Progress', 'Done') | حالة المهمة داخل لوحة كانبان |
| `effort` | INTEGER | DEFAULT 0 | الجهد التقديري بالساعات (لحساب العضو الخامس) |

#### 3.4 جدول سجل الأنشطة (`activity_logs`)
يتابع كافة التغييرات والتحركات التي تتم على المهام.
* **المفتاح الأساسي:** `id`
* **المفاتيح الأجنبية:**
  * `task_id` يحدد المهمة التي تم تعديلها.
  * `user_id` يحدد المستخدم الذي قام بالإجراء.

| اسم الحقل (Column) | نوع البيانات (Data Type) | القيود (Constraints) | الوصف |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | المعرف الفريد للسجل |
| `task_id` | INTEGER | FOREIGN KEY &rarr; `tasks(id)` ON DELETE CASCADE | معرف المهمة المعنية |
| `user_id` | INTEGER | FOREIGN KEY &rarr; `users(id)` | معرف المستخدم الذي قام بالعملية |
| `action` | TEXT | NOT NULL | نوع الإجراء (تغيير حالة، تعديل أولوية، إسناد) |
| `timestamp` | TEXT | DEFAULT CURRENT_TIMESTAMP | تاريخ ووقت العملية |

### 4. عمل العضو الأول: المشروع والمهام وقاعدة البيانات
#### 4.1 إدارة الاتصال والعمليات
* **DatabaseConnection.java**: مسؤول عن الاتصال بقاعدة بيانات SQLite (`project_management.db`) ويوفر الدالة `getConnection()` لفتح الاتصال.
* **DatabaseInitializer.java**: ينشئ جداول قاعدة البيانات المذكورة في (قسم 3) تلقائيًا عند تشغيل التطبيق لأول مرة إذا لم تكن موجودة؛ مع تفعيل خاصية `PRAGMA foreign_keys = ON;` لضمان سلامة العلاقات وحذف المهام التابعة تلقائيًا (`CASCADE`).
* **DatabaseTest.java**: ملف اختبار شامل يغطي إنشاء وقراءة وتعديل وحذف المشاريع والمهام والمهام الفرعية على مستويين (`SubTask` و`SubSubTask`)، وقد انتهى آخر تشغيل بنجاح (**Process finished with exit code 0**).

#### 4.2 نموذج البيانات (model)
* **Project.java**: يمثل المشروع (الاسم، الوصف، تاريخ البدء، تاريخ الانتهاء) وقائمة المهام التابعة له، ويحتوي على الدالة `addTask()` لإضافة مهمة للمشروع.
* **Task.java**: يمثل المهمة بكافة خصائصها البيانية ويدعم العلاقة الهرمية بين المهام عبر الدالة `addSubTask()` التي تربط المهمة الفرعية بالمهمة الأم برمجيًا تمهيدًا لحفظها في حقل `parent_task_id`.

#### 4.3 خدمة إدارة المشروع (service)
* **ProjectManager.java**: يوفر العمليات الأساسية لإنشاء وقراءة وتعديل وحذف المشاريع والمهام والمهام الفرعية، مع دعم مستويات متداخلة، كما يضمن عند حذف المهمة الرئيسية حذف جميع مستويات المهام التابعة لها تلقائيًا من قاعدة البيانات.

#### 4.4 إعداد Maven
* تمت إضافة Maven للمشروع مع مكتبة SQLite JDBC (الإصدار 3.53.4.0)، ويعتمد المشروع على Java 25.

### 5. عمل العضو الثاني: المصادقة وتسجيل المستخدمين وإسناد المهام
#### 5.1 العمليات والخدمات
* **UserDatabaseSetup.java**: يضمن تهيئة جدول `users` بالقيود المطلوبة داخل قاعدة البيانات والتأكد من تكامله مع جدول المهام.
* **User.java**: يمثل المستخدم (Entity) داخل النظام ويحتوي على بياناته الأساسية.
* **UserManager.java**: تسجيل المستخدمين، تسجيل الدخول والتحقق من بيانات الدخول، وتشفير كلمات المرور باستخدام الخوارزمية الآمنة `PBKDF2WithHmacSHA256` لمنع تخزين الكلمات بنصوص صريحة.
* **AssignmentManager.java**: يتيح إسناد المهام أو المهام الفرعية لأعضاء الفريق من خلال تحديث حقل `assigned_user_id` في جدول المهام والتحقق من صلاحيات العمليات.

---

### 6. عمل العضو الثالث: لوحة كانبان وسجل النشاط
#### 6.1 لوحة كانبان (Kanban Board)
* **KanbanBoard.java**: يدير حالات المهمة الثلاث (`To Do`, `In Progress`, `Done`)، ويتيح نقل المهام ديناميكيًا بين الأعمدة وتحديث حقل `status` في جدول `tasks` داخل قاعدة البيانات مباشرة.

#### 6.2 سجل النشاط (Activity Log)
* **ActivityLog.java**: يمثل سجل التغييرات على المهام (مثل تغيير الحالة، تعديل الأولوية، أو إعادة الإسناد) ويحفظ التاريخ والوقت والمستخدم المسؤول عن التعديل.
* **LogManager.java**: الخدمة المسؤولة عن كتابة السجلات في جدول `activity_logs` وقراءتها لضمان الشفافية ومتابعة سير العمل ومراقبة أداء الفريق.

---

### 7. عمل العضو الرابع: خوارزميات ترتيب المهام
#### 7.1 الفرز والترتيب المخصص
* **MergeSort.java**: دالة فرز يدوية مبنية على تقنية فرّق تسد لترتيب المهام بناءً على تاريخ التسليم (`due_date`) بكفاءة زمنية مستقرة قيمتها `O(N log N)`.
* **QuickSort.java**: دالة فرز يدوية سريعة لترتيب قائمة المهام بناءً على مستوى الأولوية الرقمي (`priority`) مع اختيار العنصر المحوري (`Pivot`) بذكاء لتقليف تعقيد الحالات الحرجة.
* **النتيجة**: تتيح الواجهة لمدير المشروع عرض المهام مرتبة ترتيبًا مخصصًا دون الاعتماد على الدوال الجاهزة في لغة جافا، مما يثبت الفهم العملي لتراكيب البيانات.

---

### 8. عمل العضو الخامس: حساب الجهد بتقنية فرّق تسد
#### 8.1 الحساب العودي لشجرة المهام
* **EffortCalculator.java**: يطبق خوارزمية فرّق تسد (`Divide and Conquer`) عبر ميثود عودية (`Recursive Method`) تمر على المهمة الأساسية وتجمع قيم الجهد (`effort`) المخزنة في جميع المهام الفرعية (`SubTasks`) والمهام الفرعية التابعة لها (`SubSubTasks`) عن طريق استعلام شجرة المهام من قاعدة البيانات.
* **النتيجة**: يضمن هذا التصميم حسابًا دقيقًا وسريعًا لإجمالي الساعات المطلوبة لإنجاز المشروع بالكامل بالاعتماد على التفكيك الهرمي المطبق بقاعدة البيانات.
